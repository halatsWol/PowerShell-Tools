TOPIC
    about_TempDataCleanup

SHORT DESCRIPTION
    The TempDataCleanup PowerShell module is designed to clean up temporary files from both user profiles and system folders. It supports local and remote execution, making it useful for freeing up disk space and enhancing system performance across multiple machines. By using this module, you can automate the removal of temporary files, ensuring a cleaner, more efficient environment.


LONG DESCRIPTION
--------------
    Invoke-TempDataCleanup:
    This core function handles the cleanup of temporary files in user profiles and, optionally, system folders, system logs, and software-distribution content caches. Switches select what is included; without them only user-profile temp is cleaned. This function supports remote execution through PowerShell remoting.

    Deletion is guarded and long-path safe: a drive root, the Windows directory, and System32 are always refused. Locked user-profile files are skipped (best-effort). Locked files in the system folders (IncludeSystemData / IncludeSystemLogs) and the content caches (ContentCacheCleanup) are scheduled for deletion on the next reboot, so a restart is required to finish clearing those.


    Parameters:
    -----------
    - ComputerName (Optional): Specifies the name of the computer to run the cleanup on. Accepts PipeLine and Array input. If Null/Empty String ("") (except via Pipeline), or whitespace it will default to Local Host. With more than one computer, all devices are cleaned in parallel background jobs; instead of step output, each device prints one line (name, additional and total free space, or the failure reason) when it has finished. Duplicates and local aliases are cleaned only once.
    - IncludeSystemData (Optional): When this switch is used, system folders (such as Windows Temp and SoftwareDistribution\Download) will also be cleaned up. Prefetch is not cleared: Windows maintains it itself, and clearing it only slows down the next start of every application. The Windows Update and BITS services are force-stopped while SoftwareDistribution\Download is emptied (an interrupted download is simply fetched again) and started again afterwards; an update installation in progress is never interrupted but waited for up to 10 minutes; if it is still running then, the folder's contents are deleted at the next boot instead. Together with ContentCacheCleanup, that folder is emptied once, by the content cache cleanup.
    - IncludeSystemLogs (Optional): When this switch is used, system log files and reporting folders (such as C:\Windows\Logs, C:\Windows\Minidump, and the Windows Error Reporting queues) will also be cleaned up. Logs held open by Windows services are scheduled for deletion on the next reboot.
    - ContentCacheCleanup (Optional, alias IncludeCCMCache): When this switch is provided, the cleanup will also clear the content/download caches of the software-distribution systems detected on the device: ConfigMgr/SCCM (ccmcache), Windows Update (SoftwareDistribution\Download), Adaptiva OneSite, and the Intune Management Extension. The ConfigMgr cache is relocation-aware (found via WMI, the Software Center COM API, the registry, or the default under the Windows directory), so a moved cache (e.g. D:\SCCMCache) is found instead of assuming C:\Windows\ccmcache.
    - IncludeBrowserData (Optional): When this switch is used, the browser caches of Edge, Chrome, Firefox, Opera, Vivaldi, Brave and IE will also be cleaned up. Saved site data (Firefox site storage, IE cookies) is only cleared after confirming a prompt, or with -ConfirmWarning.
    - IncludeMSTeamsCache (Optional): When this switch is used, Microsoft Teams cache files will also be cleaned up. A running Teams (new Teams, any signed-in user) is closed first, because its cache is locked; the users concerned are named in a warning and in the log.
    - IncludeIconCache (Optional): When this switch is used, the User Icon & ThumbCache will also be cleaned up.
    - IncludeAllPackages (Optional): When this switch is used, all packages in $env:localappdata\Packages\ will be cleaned up.
    - LowDisk (Optional): Performs a System Cleanup using CleanMgr with basic settings. Additionally performs  `IncludeSystemData`, `ContentCacheCleanup` and `IncludeIconCache`
    - VeryLowDisk (Optional): Performs a System Cleanup as with 'LowDisk' with advanced settings. Additionally clears all Recycle-Bins and runs also -AutoClean
    - AutoClean (Optional): Executes CleanMgr Upgrade Cleanup additional to `IncludeSystemData`, `ContentCacheCleanup` and `IncludeIconCache`
    - ConfirmWarning (Optional): Bypass the confirmation prompts of 'VeryLowDisk', 'IncludeAllPackages' and the browser site data of 'IncludeBrowserData', all answered with yes (for unattended runs)
    - init (Optional): When specified, the Config-File will be Written to the Module-Root-Directory. This will NOT overwrite an existing Config-File.
    - ThrottleLimit (Optional): Maximum number of devices cleaned at the same time when more than one computer is given (1-100, default 10). Further devices start as soon as a running one has finished.
    - DeviceTimeoutMinutes (Optional): With more than one computer, the maximum run time per device (5-1440 minutes, default 90). A device still running after that is stopped and reported as failed.
    - Quiet (Optional): Suppresses all console output (progress, summary lines, warnings); only errors and, with -PassThru, the result objects remain, e.g. for scheduled or scripted runs. Confirmation prompts are still shown, use -ConfirmWarning to bypass them.
    - PassThru (Optional): Returns one TempDataCleanup.Result object per device after all devices have finished. Without it nothing is returned; the per-device lines on the console show the outcome.
    - Credentials (Optional): when Specified, this will prompt for User-Credentials that will be used for the Remote-Access
    This can be used e.g. by passing on a credential Object `-Credentials (Get-Credential)`


EXAMPLES
    Example 1: Clean up temporary files from user profiles on the local machine
    -----------------------------------------------
    Invoke-TempDataCleanup -ComputerName "localhost"

    Example 2: Clean up temporary files from user profiles on a remote computer
    -----------------------------------------------
    Invoke-TempDataCleanup -ComputerName "Computer01"

    Example 3: Clean up temporary files from user profiles on a Computer using Pipeline (will not default to localhost if not specified)
    -----------------------------------------------
    "comp1","comp2","comp3" | Invoke-TempDataCleanup

    Example 4: Clean up temporary files from user profiles on a Computer using Array (will default to localhost if element is null or empty "")
    -----------------------------------------------
    Invoke-TempDataCleanup -ComputerName comp1,comp2,"",comp3

    Example 5: Perform a cleanup (user temp and system temp files) on the local computer
    -----------------------------------------------
    Invoke-TempDataCleanup -ComputerName "localhost" -IncludeSystemData

    Example 6: Perform a full cleanup (user temp, Browser Cache, MSTeams Cache and system temp files) on a remote computer
    -----------------------------------------------
    Invoke-TempDataCleanup -ComputerName "Computer01" -IncludeSystemData -IncludeBrowserData -IncludeMSTeamsCache

    Example 7: Clean user/system temp, system logs, and software-distribution content caches (locked items deferred to reboot)
    -----------------------------------------------
    Invoke-TempDataCleanup -ComputerName "Computer01" -IncludeSystemData -IncludeSystemLogs -ContentCacheCleanup


NOTES
    The script is provided "as-is" and is not supported by Microsoft.
    Always test the script thoroughly in non-production environments to prevent unintended file deletions or other system disruptions.
    Incorrect use of the script may cause system instability or data loss.

    Deletion is guarded (it refuses drive-root / Windows / System32 targets) and long-path safe. Locked files under the system folders (-IncludeSystemData / -IncludeSystemLogs) and the content caches (-ContentCacheCleanup) are scheduled for deletion on the next reboot, so a restart is required to finish. Locked user-profile files are skipped (best-effort) and are never queued for boot-time deletion.

    !! If in Windows Terminal Settings, Terminal is set as Default Terminal Application, Powershell 5.1 may throw an error instead of prompting for User Credentials.
    As workaround you can pass on credentials using the `Get-CredentialObject` from the CredentialHander-Module (https://github.com/halatsWol/PowerShell-Tools/tree/main/modules/CredentialHandler)

    Example:
    -----------------------------------------------
    Invoke-TempDataCleanup -Computername myRemoteDevice1 -Credentials (Get-CredentialObject)


    Requirements:
    -------------
    - Windows PowerShell: This module requires PowerShell to run both locally and on remote machines.
    - WinRM: Windows Remote Management (WinRM) must be enabled and configured on remote computers to run the function remotely.
    - Administrative Privileges: Some tasks, especially those involving system folders, may require administrative rights on the target machine.
    - Network Configuration: If using IP addresses or non-standard network setups, ensure proper configuration for remote execution.

    Warning:
    -------------
    - ALWAYS REVIEW AND UNDERSTAND THE CODE BEFORE EXECUTING IT.
    - DO NOT RUN THIS SCRIPT ON PRODUCTION SYSTEMS WITHOUT PROPER TESTING.

    - NEVER MAKE CHANGES TO SYSTEM SETTINGS OR DELETE FILES WITHOUT PROPER AUTHORIZATION.
